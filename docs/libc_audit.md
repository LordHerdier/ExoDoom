# libc audit — what Doom calls, and what answers

**SCRUM-72.** Companion spreadsheet: [`libc_audit.csv`](libc_audit.csv)
(61 rows), generated by [`gen_libc_audit.py`](gen_libc_audit.py) from the same
data this page narrates. Re-run `python3 docs/gen_libc_audit.py` after editing
the table in that script; don't hand-edit the CSV.

This is the input the Kernel-libc epic was waiting on. It answers "what does
Doom actually need?" with a list rather than a guess.

---

## 1. How this was derived

Not by grepping for function names — grep cannot tell a live call from one
inside `#if ORIGCODE`, and it silently misses calls made through macros
(`DEH_snprintf` is `#define`d to `snprintf`, `DEH_String` to nothing at all).

Instead the list comes from the linker's own answer to the question, which
cannot miss a call or invent one:

```sh
x86_64-elf-nm --defined-only build/doom/*.o   # what Doom defines itself   (1939)
x86_64-elf-nm -u             build/doom/*.o   # what it leaves undefined    (845)
comm -23 <undefined> <defined>                # what it needs from outside    (52)
```

Those 52 external symbols are the whole requirement: **17 libc functions that
already work, 23 that don't, 2 objects (`stdout`/`stderr`), the 6 `DG_*`
platform callbacks, `_GLOBAL_OFFSET_TABLE_`, and two Doom globals from the
networking files that aren't vendored (`drone`, `net_client_connected`).** No
other libc function reaches an object file.

Status was then cross-referenced against `nm --defined-only` over the kernel's
own objects, and the behavioural notes against the actual implementations in
`src/string.c`, `src/ctype.c`, `src/stdlib.c` and `src/stdio.c`.

> Deriving the list at all required all 79 files under `src/doom/` to
> compile, which is **SCRUM-64** (PR #66, now merged). The two are
> companions: it makes the objects, this explains what they still need.
>
> So several files this audit names are SCRUM-64's, not older shim work —
> worth knowing when tracing a claim back to a commit:
>
> - `src/errno.c` and `src/errno.h`, behind §4's `errno` paragraph and the
>   `EISDIR` discussion.
> - The `Header` column in the CSV names `strings.h` for `strcasecmp` /
>   `strncasecmp` and `sys/stat.h` for `mkdir`. Both *headers* are
>   SCRUM-64's; the *implementations* behind the first two are older
>   (`src/string.c`, SCRUM-11), so only the header spelling moved.
> - §5's account of the doom compile pass dropping `-mno-sse`.
>
> None of the status columns depend on it. What is implemented and what is
> missing would read the same either way.

Call-site counts in the CSV are grep, and are the one soft number — they count
text, including occurrences in compiled-out blocks. Where grep and the symbol
data disagree, the row says so, and those rows are marked `DEAD`.

## 2. Summary

| Status | Count | Meaning |
|---|---:|---|
| `REAL` | 4 | Implemented, behaves as the standard requires |
| `REAL*` | 13 | Implemented, with a behavioural difference worth knowing |
| `MISSING` | 25 | Referenced, nothing defines it → link error (23 functions + `stdout`/`stderr`) |
| `PLATFORM` | 6 | Not libc — the `DG_*` callbacks the port supplies |
| `DEAD` | 13 | Called only from code the build compiles out, or never called |

**17 of the 40 libc functions Doom actually reaches are done.** The 23 missing
ones are not 23 separate problems: **14 of them are stdio**, and under the
memory-mapped-WAD design in `docs/architecture.md` §7 six of those
(`fopen`, `fclose`, `fread`, `fseek`, `ftell`, `fwrite`) collapse into pointer
arithmetic over the mapped multiboot module rather than real file I/O.

## 3. Three findings that matter more than the counts

### 3.1 `printf`'s missing precision will stop the game starting

This is the highest-severity item in the audit, and it is not a missing
function — it is a gap in one that is marked done.

`src/stdio.c`'s `kvprintf` supports `%d %i %u %x %p %c %s %%` with field width
and the `-` / `0` flags. It has **no precision, no length modifiers, and no
`%X`/`%o`/`%f`**. An unsupported conversion falls to the `default:` branch,
which echoes the `%` and the character verbatim — **and does not consume the
vararg.** Every later conversion in that same call then reads the wrong
argument.

Eight occurrences in `src/doom/` hit this:

| Spec | Where | What it builds |
|---|---|---|
| `%.3d` | `hu_stuff.c:297` | `STCFN%.3d` — **HUD font lump names** (`STCFN033`…) |
| `%2.2d` | `wi_stuff.c:1564` | `CWILV%2.2d` — intermission level-name patches |
| `%.2d` ×2 | `wi_stuff.c:1596` | `WIA%d%.2d%.2d` — intermission animation lumps |
| `%f` | `m_config.c:1699` | config file writer, `DEFAULT_FLOAT` values |
| `%f` | `g_game.c:2265` | `I_Error` timedemo message |
| `%.8s` | `m_misc.c:226` | a truncation warning (cosmetic) |
| `%o` | `m_misc.c:194` | `sscanf` octal parse (moot — `sscanf` is missing anyway) |

The first three are the problem. They run through `DEH_snprintf` → `snprintf`
→ `vsnprintf`, so they inherit `kvprintf`'s gaps. `HU_Init` calls
`W_CacheLumpName` on each generated name; with `%.3d` echoed literally the
name becomes `STCFN%.3` (truncated to the 9-byte buffer) for **every** glyph,
no such lump exists, and Doom dies in `I_Error` before the HUD ever draws.

**So implementing `snprintf` is necessary but not sufficient — it must be
implemented with precision support, or the lump names it builds are wrong.**
That is a constraint on SCRUM-21 that wasn't previously written down.

A defensible smaller fix: make the `default:` branch consume an `int` vararg
so at least the desynchronisation stops. It would still print the wrong text,
but a wrong level name is survivable where a shifted argument list is not.

### 3.2 Eight functions have no prototype, and four of them return pointers

`strdup`, `strrchr`, `strstr`, `calloc`, `atof`, `exit`, `system` and
`strncmp` are called with **no declaration in scope**. Under gnu99 that is a
warning, not an error, and the implicit declaration is `int f()`.

For the four that return pointers — `strdup`, `strrchr`, `strstr`, `calloc` —
**the 64-bit return value is truncated to 32 bits** at the call site. The
compiler already says so: 10 `makes pointer from integer without a cast`
warnings across `d_iwad`, `m_argv`, `m_config`, `m_misc` and `w_wad`. `atof`
is worse in kind: declared `int`, its `double` return is read from the wrong
place entirely.

These would be live bugs the moment the functions exist, and they would look
like heap corruption rather than a missing prototype. **The declarations are
more urgent than the implementations**, and four of the eight bodies
(`strdup`, `strncmp`, `strrchr`, `strstr`) are a few lines each.

### 3.3 `memcpy`/`memset` are byte-at-a-time, on the per-frame path

Both are correct and both are simple `while (n--)` loops. Doom calls them from
`r_draw`, `v_video`, `f_wipe` and `i_scale` on framebuffer-sized spans every
frame at 35 Hz. This is the shim's most likely *performance* problem and the
one place where "correct" and "good enough" may diverge. Worth measuring
before optimising — not worth assuming either way.

## 4. What's implemented, and how it differs

Full detail per function is in [`libc_audit.csv`](libc_audit.csv). The
deviations worth knowing:

| Function | Difference from standard |
|---|---|
| `malloc` | Two allocators behind one name: a one-way bump allocator until `page_alloc_init()` runs, `heap_alloc` after. Bump allocations are 4K-aligned and can never be freed. Doom allocates long after the handoff, so it always gets the real heap. |
| `free` / `realloc` | Silently refuse a pointer into the permanent bump region — a serial warning and a no-op (`free`) or `NULL` (`realloc`), not a fault. |
| `atoi` | Clamps to `INT_MAX`/`INT_MIN` on overflow instead of being undefined. Accumulates in `long` so the clamp is exact. Never sets `errno`. |
| `abs` | `abs(INT_MIN)` returns `INT_MIN` — defined-but-negative rather than UB. No Doom caller passes it. |
| `strcasecmp`, `strncasecmp`, `toupper` | ASCII / C locale only; no locale support exists. Correct for the WAD-lump and argv comparisons Doom uses them for. |
| `printf`, `putchar`, `puts` | Write to COM1 serial — there is no `stdout`. Plus §3.1. |
| `strncpy` | Standard, including the standard footgun: no NUL terminator when the source is at least `n` bytes. |
| `memcpy`, `memset` | Correct, byte-at-a-time. See §3.3. |

`errno` deserves its own line: it exists as an object (`src/errno.c`, added by
SCRUM-64) and **nothing ever sets it**. `m_misc.c`'s `M_FileExists` tests
`errno == EISDIR` to distinguish "open failed" from "open failed because it's a
directory", so it always reads false. That is the correct answer for a shim
with no directories, but it is right by accident, and it will stay right only
while `fopen` is missing.

## 5. Prerequisite this audit surfaced: SSE is not enabled

Not a libc gap, but it blocks everything downstream and no ticket owns it.

The x86_64 SysV ABI returns `float` in `xmm0`. `m_config.c`'s
`M_GetFloatVariable()` returns a `float`, so it cannot compile under the
kernel's `-mno-sse` — and no flag combination avoids this (`-msoft-float` and
`-mfpmath=387` both still hit the ABI). SCRUM-64 therefore drops `-mno-sse`
for the Doom compile pass; the kernel build keeps it and is unaffected, since
no `src/*.c` uses a float.

**At runtime this is unsatisfied.** `src/boot.s` sets only CR4.PAE — never
CR4.OSFXSR (bit 9) or CR4.OSXMMEXCPT (bit 10), and never clears CR0.EM — so
the first SSE instruction any Doom object executes raises `#UD`. Only 4 of the
79 objects contain float arithmetic (18 instructions), but allowing SSE also
lets GCC inline struct copies with `movaps`/`movdqa`/`pxor` engine-wide
(~143 more). Both classes need the same bits set.

Enabling SSE, and deciding whether XMM state must be preserved across the
syscall and interrupt paths, is a hard prerequisite for running any of this.
**It needs a ticket.**

## 6. Suggested order of work

Ordered by what unblocks the most for the least effort, not by call count.

1. **Prototypes for the eight undeclared functions** (§3.2) — near-zero effort,
   removes a class of 64-bit truncation bugs before it can bite. Bodies for
   `strdup`, `strncmp`, `strrchr`, `strstr` are a few lines each and can ride
   along.
2. **`snprintf`/`vsnprintf` *with precision*** (SCRUM-21, constrained by §3.1)
   — `kvprintf` already takes an arbitrary sink, so the sink is easy; the
   precision support is the actual work, and without it the WAD lump names
   Doom builds are wrong.
3. **A ticket for SSE enablement** (§5) — nothing runs until this exists.
4. **`stderr`/`stdout` + `fprintf`/`vfprintf` onto serial** — 65 `fprintf`
   call sites, but almost all are `fprintf(stderr, ...)` diagnostics that need
   no file at all. Large win, small change.
5. **The memory-mapped WAD reader** (`docs/architecture.md` §7) — `fopen`,
   `fread`, `fseek`, `ftell`, `fclose`, `feof` over the multiboot module.
   Collapses 6 of the missing functions into pointer arithmetic.
6. **`sscanf`** — the one genuinely from-scratch item; no parsing machinery
   exists in the shim. Needs `%d`, `%x`, `%o` and `%s`.
7. **The leftovers** — `mkdir` (no-op returning 0), `system` (return −1),
   `exit` (onto `exo_exit`, SCRUM-155), `calloc`, `atof`, `remove`/`rename`
   (savegame rotation only), `fwrite`.

The `DG_*` callbacks are tracked separately: SCRUM-73 (`DG_Init`), SCRUM-74
(`DG_GetTicksMs`/`DG_SleepMs`), and the video/input ones alongside them.
